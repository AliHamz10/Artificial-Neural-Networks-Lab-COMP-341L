Abstract

This work fine-tunes a small language model to behave as an academic assistant that explains Computer Science concepts in a strict teaching style. A curated instruction dataset is written manually and used to train LoRA adapters on distilgpt2. The system is evaluated by comparing base vs fine-tuned outputs on the same prompt, and analyzed through targeted failure cases. A manual improvement cycle is attempted via dataset refinement.

1. Objective & Constraints

  • Improve clarity, style consistency, and reduce overconfident guessing.
  • Use a small model that can be fine-tuned under Colab constraints.
  • Do not submit unmodified AI text as “dataset explanations”; explanations are written manually.

2. Teaching Style Definition

Template enforced in every dataset response:

  • Step-by-step explanation
  • Real-life analogy
  • Tiny example (1–3 lines)
  • Common mistake
  • One-line recap

3. Dataset (Manual)

The dataset is stored as JSONL with fields instruction and output. Each output is written to follow the defined teaching style.

Dataset Samples Purpose
v1 25+ Primary style tuning across CS topics
v2 5 Failure-driven improvement (DP state selection + uncertainty handling)

4. Model Selection

Model: distilgpt2. Selected for fast iteration and low compute cost. The primary limitation is reduced factual reliability and higher repetition risk compared to larger LLMs.

5. Fine-Tuning Strategy (LoRA)

LoRA trains a small number of additional parameters (adapters) while freezing the base model. This reduces memory usage and makes fine-tuning feasible on Colab GPUs while enabling direct comparison between base and adapted behavior.

6.4 Analysis

  • Clarity: The base response is generic and does not explain DP. Fine-tuned outputs are off-topic or repetitive.
  • Hallucination/overconfidence: The tuned model does not reliably adopt a cautious stance; it generates “article-like” filler without grounded explanation.
  • Style consistency: The strict template (steps, analogy, example, mistake, recap) is not consistently produced, implying insufficient data/epochs/decoding stability for robust style control.

7. Failure Analysis (2 Cases)

Two prompts were used to expose errors: (i) proof-like requests and (ii) requests for precise external facts.

7.1 Proof request failure

Asking for a proof (e.g., “prove DP always gives optimal answer”) fails because the dataset does not teach formal proof framing (optimal substructure assumptions, state definition, recurrence justification). This is a data coverage gap plus a small-model limitation.

7.2 External-fact precision failure

Requests like “best-known TSP algorithm complexity and discovery year” encourage hallucination because the model lacks reliable access to up-to-date citations. Without uncertainty examples, it may guess. This is primarily a model limitation and training-data policy gap (missing “I don’t know” patterns).

8. Manual Improvement (One Fix)

The v2 dataset adds examples that explicitly teach (a) DP state selection and (b) hallucination awareness / safer behavior. However, since v2 is only a few samples, it is not sufficient to reliably override unstable generation behavior.

9. Key Insights

  • With tiny datasets, fine-tuning can amplify repetition and irrelevant patterns instead of enforcing structure.
  • Style control requires more high-signal examples, especially for the evaluation concept (DP here).
  • Safer academic behavior benefits from explicit “uncertainty/ask clarifying question” training examples.
